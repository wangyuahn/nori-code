Read your own department: the peer Sessions hired alongside you, and the child Sessions you hired yourself.

`colleagues` lists your peers — same parent Session as you, reachable by session id with `TeamChat` or `TeamDM` — with each one's role, observable `idle`/`running` status, assigned task, and whether it has reported to your shared parent yet. Use it to see who owns which part before you touch a file near their scope, and to name the peer a handoff belongs to. `parent_agent_id` is the parent Session that hired you.

`members` lists the child Sessions you hired: identity, `idle`/`running` status, assigned task, latest explicit TeamDM report status (`unreported`, `completed`, `blocked`, or `needs_decision`), report summary, and whether you have received that report. Ordinary TeamDM messages are not classified as reports. `agent_id` and `session_id` are the same child session id.

A `running` member is still working: let it finish rather than repeating or taking over its task, and read its `TeamDM` or query this tool again.
